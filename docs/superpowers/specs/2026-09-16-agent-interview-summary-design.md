# Klonet Agent 面试总结材料设计

## 目标

生成一份面向技术面试的中文 Word 材料。它既应能作为项目概述和讲解提纲，也应能支撑围绕 RAG、Agent 编排、记忆、受控运维和评测的追问。

## 叙事原则

- 以“解决 Klonet 运维知识分散、现场诊断依赖经验且高权限操作风险高”的业务问题为主线。
- 对每项技术严格区分“已实现能力”“设计取舍”“后续演进”，避免将通用知识或规划写成项目事实。
- 使用解释性、可口述的行文：先说明问题，再解释选择，最后落到代码中的工程机制。
- 技术结论以当前源码、正式设计文档和评测材料为依据；性能指标只引用已有评测结果和其适用范围。

## 文档结构

1. 项目定位与业务背景
2. Agent 总体架构与 Profile 隔离
3. 端到端工作流：Mentor、Ops 与 ops-privilege
4. RAG 与结构化意图路由
5. 受控高权限变更：证据、计划、绑定、确认、执行、验收
6. 记忆、上下文和可观测性
7. 真实能力、评测证据与边界
8. 关键难点、迭代经验与优化方向
9. 高频面试问答

## 视觉和排版

- A4 中文技术材料，采用 Word 语义化标题、目录和页码。
- 至少包含三张原生绘制的流程图：总体架构、RAG 路径、高权限闭环。
- 用表格区分各 Profile、事实与设计边界，以及评测证据。
- 关键术语在首次出现时给出简洁解释，正文保持适合口述的段落节奏。

## 真实性边界

- Mentor、Coding 与 Ops Profile 共用 Runtime；高权限闭环仅在 `ops-privilege` 路径中适用。
- 真实服务器评测覆盖只读发现和审批前计划；实际破坏性变更在隔离合同中验证，不称为线上实操成功。
- RAG 使用本地 JSONL 索引与 BM25/向量/精确匹配/RRF/可选 rerank，不描述为向量数据库。

## 验收

- Word 可打开、标题层级正确、目录与页码可用。
- 所有数值指标、技术能力和限制与源码/评测报告一致。
- 文档能在 10–15 分钟内完整讲述，且高频追问可直接从对应章节展开。
