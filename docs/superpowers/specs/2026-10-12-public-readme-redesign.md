# Klonet Agent 公开仓库 README 重构设计

## 目标

将当前按开发时间持续累积的 README 重构为适合项目老师和技术面试官阅读的公开仓库首页。读者应能在数分钟内理解项目解决的问题、核心能力、技术架构、运行方式和工程完成度，同时仍能查阅已有的技术演进记录。

## 目标读者

- 评估课程设计完整度、技术路线与实验过程的项目老师。
- 关注个人贡献、工程能力和系统设计思路的技术面试官。

## 内容结构

README 前半部分采用作品集式结构：

1. 项目名称、一句话定位与当前状态。
2. 项目背景，以及 Klonet Agent 解决的具体问题。
3. 核心亮点，突出多角色 Agent、混合 RAG、上下文治理、长期记忆、安全工具和可观测性。
4. 系统架构图及主要数据流。
5. Mentor、Coding、Ops 三种模式的职责边界。
6. 快速开始、环境配置和常用命令。
7. 项目结构、测试与评估、相关文档入口。
8. 当前限制、路线说明和许可证状态。

README 后半部分保留原有技术信息，但按主题重新归类为“技术实现与演进记录”。冗长配置、生产环境细节和历史实现说明使用折叠区块，降低对首次阅读的干扰。

## 表达与安全原则

- 以中文为主，关键技术首次出现时保留英文名称。
- 优先写可由当前源码、配置、测试或仓库文档验证的事实，不虚构指标、在线演示、截图或许可证。
- 快速开始命令不得包含开发者本机绝对路径。
- 环境变量示例只使用占位符；不展示真实密钥、个人服务器地址或带有部署身份的信息。
- 将特定供应商和生产路由细节降级为高级配置或历史记录，避免它们抢占项目定位。
- 保留开发规范入口，明确公开贡献者应先阅读的工程约束。

## 修改范围

- 重写根目录 `README.md` 的组织结构与文案。
- 复用现有仓库内的设计、运维和评测文档链接。
- 不修改业务代码、配置文件、测试文件或当前其他未提交内容。
- 不新增未经用户确认的许可证，也不宣称项目已经具备尚未验证的能力。

## 验收标准

- README 开头能独立回答“这是什么、为什么做、有什么特点”。
- 新用户可根据快速开始完成依赖安装、环境配置并启动至少一种模式。
- 架构和各 Agent 的职责与当前代码一致。
- 原 README 中仍有价值的技术信息可被找到，且不妨碍主线阅读。
- 所有相对链接有效；示例中不包含真实凭据或本地绝对路径。
- Markdown 标题层级、代码块和折叠区块结构完整。
