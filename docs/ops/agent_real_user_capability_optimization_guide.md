# Agent 能力根因优化指南

## 目标

本指南用于约束后续优化方式：先确定失败属于哪个共享层级，再修改该层的领域模型或合同；禁止按单个目录、端口、组件名或用户话术增加旁路。

## 已完成的根因重构

### 1. 用共享 RuntimeInventory 代替运行证据文本猜测

Discovery、Verifier 和 Response 共同使用结构化运行实例模型。模型以规范化 `project_root` 为身份，保存角色、PID、端口和健康接口状态，统一回答平台数量、单实例状态、同名实例、无 Screen 和根路径 404 等问题。

效果：运行清单不再经过 LLM 摘要后丢行，也不会出现“数量为 4、只列 2 个”的矛盾。

### 2. 领域探针优先于通用命令分类

运行健康目标先执行 `running_platforms`，只有领域模型无法回答时才进入通用 Discovery。Verifier 可直接验证完整清单，无需让模型重新猜测证据是否足够。

效果：`screen -ls`、Nginx、首页 404 等信号不再覆盖后端健康标准。

### 3. 收紧运行进程身份

运行候选要求可执行文件或 argv 真正属于 Screen、Python、Gunicorn 或 Celery。仅仅在 shell 命令文本中提到这些词的观察进程不再算平台进程。

效果：Agent 自己的诊断 shell 不会被发现为新的平台实例。

### 4. RAG 是有来源和质量状态的流程证据

运行时变更要求检索证据包含可靠状态以及项目根目录、`mains`、Screen 等流程合同。`weak` 或不可用召回不能进入 Binding；实时端口、PID 和路径始终由服务器证据覆盖文档示例。

效果：Planner、Binding 和 Verifier获得同一份冻结知识证据，同时避免弱相关文档指导真实执行。

### 5. 组件采用 Manifest 和依赖拓扑，不写死四个名称

平台整体重启从 `RuntimeComponentSpec` 读取 `managed`、`default_restart`、`start_after`、Screen 后缀、命令和健康检查。组件按拓扑排序，未来新增组件使用同一结构化 Action 合同。

效果：master、celery、web_terminal、worker 和未来 metrics/audit_sink 都走同一框架。

### 6. 展示层对任意组件统一本地化

进度和计划摘要使用通用组件模式转换，不维护 master/worker 等枚举替换表。执行绑定只展示缩略动作，完整参数通过详情命令查看；确认执行后回执展示实际脱敏命令、cwd、返回码和验收结果。

效果：新组件不会因缺少专用替换规则发生中英文漂移。

### 7. 失败是主工作流状态，不是异常旁路

Planning、Binding、Execution、Verification 的失败统一形成 `FailureOutcome`，保存技术原因、环境是否改变、已完成/失败/跳过步骤和恢复选项。自然语言“选择 1”“查看刚才失败的详细原因”“取消这次操作”直接操作最新失败状态，并在需要时重新进入 Discovery 和审批。

效果：失败不会被隐藏成一句“有限次数校正后失败”，用户始终能参与下一轮决策。

### 8. 评测基础设施也必须可重复

评测器为每个场景创建独立 pytest 临时目录和会话标识，隔离合同与真实会话分别记账。真实变更请求永不自动发送确认口令。

效果：fixture 准备失败不会伪装成产品失败，评测也不会意外修改服务器。

## 后续优化优先级

### P1：压缩因果诊断轮次

当前 C09 能自主得到根因，但用了 6 轮补证。应将“异常堆栈中的路径 → 配置定义 → cwd 展开 → 文件存在性/权限”编译为可复用的诊断证据图，由 Verifier 一次返回尚缺的最小探针集合；不要简单降低最大循环次数。

验收标准：同一问题不重复请求语义等价的日志或进程证据；形成完整因果链后立即停止。

### P2：为真实多轮输入增加专用评测驱动

当前隔离合同已验证持久化追问，真实会话应增加支持等待每轮回答后再发送下一条消息的 PTY 驱动器，以精确验证“这个报错为什么”“你自己继续定位”等连续话术。

### P3：依赖环境自检

`requirements.txt` 已声明 `bashlex>=0.18`，但测试环境最初没有安装，导致 Shell AST 策略拒绝执行。启动和 CI 应在运行前验证强制依赖，而不是到执行阶段才返回 `shell_ast_parser_unavailable`。

## 每次修改后的固定回归顺序

1. 运行受影响层的最小失败用例。
2. 执行 35 项能力矩阵。
3. 对安全场景执行真实只读/仅规划会话，禁止自动确认。
4. 执行完整 pytest 回归。
5. 保存报告、原始会话和失败证据；若失败，回到共享根因层级继续循环。
