# Agent 真实用户需求能力测试报告

## 结论

- 清单范围：35 项（按要求不含“权限与账号能力”和“并发与鲁棒性”）。
- 最终结果：35/35 隔离能力合同通过。
- 真实服务器验收：C01–C05 只读查询全部通过；C06 成功生成完整重启计划并停在审批前；C09 在用户第一次询问时即定位到日志路径根因。
- 完整项目回归：1056/1056 通过（3 条第三方弃用警告，无失败）。
- 安全边界：真实服务器没有发送 `confirm-priv-plan`，所以没有为了评测而重启、停止或修改平台。涉及执行、故障注入和失败恢复的项目均在隔离 fixture 中验证。
- 服务器基线是测试时实时计算结果，不作为永久硬编码结果。

## 测试方法

每个场景同时采用下列证据中的一种或两种：

1. 真实 Agent 会话：使用真实用户话术调用 `ops-privilege`，保留完整终端输出。
2. 隔离能力合同：在临时目录、假进程和假端口中执行确定性测试，验证动作、审批、冻结资源、失败恢复等不适合直接破坏真实服务器的行为。
3. 完整回归：执行整个 pytest 测试集，确认架构重构没有破坏清单外能力。

评测入口：`evals/agent_real_user_capability/run_eval.py`；场景定义：`evals/agent_real_user_capability/cases.json`。

## 首轮失败与根因

首轮真实测试不是全部通过，主要问题如下：

- C01 回答把截断后的运行清单当成完整事实，数量和列举内容不一致。
- C02、C04、C05 被通用命令分类器带入无关的端口、日志或 Nginx 探针，最终出现 `Verifier ValueError` 或错误追问。
- Shell 观察命令的文本中出现 `Celery` 时，被误识别为平台运行进程，产生虚假实例。
- 动态组件的英文标题只针对 master/worker/celery/web_terminal 写了替换表，新组件会发生语言漂移。
- “查看刚才失败的详细原因”“算了，取消这次操作”没有直接进入失败状态机。
- 第一轮评测器没有创建 pytest 临时目录的父目录，把 fixture 初始化错误误报成产品失败。

这些问题按共享根因重构，未通过增加目录、端口或固定测试话术特例解决。详细设计见同目录下的优化指南。
